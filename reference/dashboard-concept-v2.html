The direction — "The Pass, grounded"

A's navy pass becomes the shell on every screen. It stays navy in light mode, the same way TopNav and the footer do. C's inset grouped rows carry everything under it. B's stepper survives as one component inside a "What's left" group, not as the page structure. Organising rule: the pass answers is this on me or on them before anything scrolls, and orange appears exactly once per screen — only when the answer is "you". The Waiting screen has no orange anywhere.

Two calls I need from you

1 · The hero line font. CLAUDE.md says Bebas Neue on every dashboard heading. Bebas is all-caps condensed, so the hero renders "APPROVE THE TIME AND PRICE" — shouting, which is the opposite of premium. Above, Bebas keeps every label, chip, numeral, nav item and button; only the single hero status line is DM Sans at −0.03em. That's one documented exception and one reversible CSS rule. Say the word and I'll put Bebas back so you can compare.

2 · The pass in light mode. It stays navy in both themes — the same .ff-on-dark trick TopNav and the footer use. Flip to Light and tell me if the navy block still reads right against the pale page, or if you'd rather it lighten with everything else.

Fixed since v1

Spacing is now a token scale — nothing in this file uses an off-scale value. The stepper connector is absolute geometry instead of a −0.6rem margin hack. The sidebar's clipped inset accent bar is replaced by a filled tint, side padding is 12px, rows are a fixed 42px, and the rail is grouped with captions. Table rows are a fixed 42px so they stop looking uneven. The real mark from public/favicon.svg replaces the placeholder wrench. A job switcher rail plus an "All your jobs" list give a multi-job client a way between them. Sign in and Create account are both drawn. Every token resolves in both themes.

Added in this pass: the Messages page — inbox grouped by live job / still-choosing / closed, an open thread with system events inline, the read-only thread using the real chatClosedReason() wording, an empty state, and the desktop two-pane.

And the two onboarding-complete screens, which replace ClientSuccess and ContractorSuccess: confirmation, next steps as the same stepper, and a "How we'll reach you" group naming every channel plus the no-SMS promise.
