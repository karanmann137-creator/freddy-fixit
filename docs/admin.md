# Admin

`AdminDashboard.tsx`, left sidebar: Health / Platform / Requests / Jobs / Picks / Accounts / Flagged chat / Disputes / Prepaid / Leads / Agents / Activity. `loadAll` checks each `Promise.all` result's `.error` and shows a banner naming the failed areas — a swallowed error used to render a silent false-empty tab. Newer tabs load in their **own** try/catch so an older DB still renders everything else.

- **Requests** — bids render read-only at **every** status (they used to vanish the moment a client picked). The accepted bid gets a green `✓ PICKED` chip; declined bids dim. **The client picks bids** — the admin assign dropdown and accept-bid buttons were removed. Pending requests carry a **"Re-send to contractors"** button (`admin_refire_request`) plus a "Re-sent N times" line; it's hidden on non-pending requests because dispatch-job refuses those and it would be a dead control.
- **Jobs** — service title, `{client} → {contractor}`, location, job code, **Read chat**, **Delete job** (`admin_delete_job`).
- **Picks** — `admin_list_picks(p_limit)`. Built on **`jobs`, not `bids`**, because a job row exists for every match (bid, rehire, or admin assign) and `jobs.created_at` IS the pick moment (`bids` has no `updated_at`). Derives `how` = `client_pick` / `rehire` / `admin_assign`, plus the winning amount and `bid_count`.
- **Accounts** — `admin_list_accounts()` lists **every `auth.users` row** (so orphans show), joined to profiles + contractors: contact, role, join/last-sign-in, request/job counts, orphaned flag, and full vetting (company, specialties, area, licence/insurance/WCB, references, experience, availability, rating/jobs/earned, pricing, `stripe_payouts_enabled`, Google reviews, AI verdict). Plus **Documents** (signed-URL buttons for the private `contractor-docs` bucket via the `contractor_docs_admin_select` policy) and **Photos** thumbnails. Approve/Deactivate (`admin_set_contractor_status`), payout diagnosis, **Delete account** (`admin-delete-account` — full wipe incl. storage under `${uid}/` across 6 buckets, then `auth.admin.deleteUser`; blocks self-delete). Orphan bar offers **finish-signup-nudge**.
- **Email contractors** — `AdminMessageModal.tsx` + **admin-message** edge fn. Recipient emails are looked up **server-side**, never trusted from the client. Every send logged to `admin_messages` (shared `batch_id`); history via `admin_list_messages`.
- **Activity** — `admin_audit_tail(p_limit)`, newest first. Every destructive admin action: account/job/request deletion, login-email change, bulk email, platform mode change, contractor status change, `admin_clear_mfa`, `assign_job`, outreach queue/import, social-bot key rotation, waitlist release. Times arrive pre-formatted as `at_local` from `ff_local_ts` — **never re-format them in the browser**, that's how two copies drift. `auditFailed` keeps a read error distinct from an empty log, because an audit trail that renders a confident "nothing here" when the query broke is worse than no trail. **There is no clear button and there must never be one**: the table has a SELECT policy and no write policy at all, and `log_admin_action` is granted to `service_role` alone — so a compromised admin session can read the log but cannot touch it. Entries start 2026-11-03; nothing before that was recorded anywhere.
- **Agents** (2026-11-04) — the background team's proposal queue and roster. Two panels, because they answer two different questions and one list could only ever answer the first: the **queue** (`admin_list_agent_actions(p_limit, p_status)`) says *what is waiting on me*, and the **roster** (`admin_agent_overview()`) says *is anything silently not running at all*. The roster is the one that earns its place — every outage on this platform has been an **absence**, and an agent that quietly stops looks identical to an agent with nothing to say. The queue cannot tell those apart, which is why the roster reads from `agent_registry`, a **declared** list, rather than from the runs it happens to have seen. `stale` is computed in the DB against each agent's own `expected_every × 1.5`, and a disabled agent is never stale, so the panel is **self-clearing** rather than red from day one.
  - Approve/reject is `admin_review_agent_action(p_action_id, p_approve, p_payload)` and it carries **`admin_guard()`** — it needs a real `auth.uid()`, so it cannot be called from a SQL session or a Cowork artifact. **That is why approvals live here and nowhere else**, with the shared `offerVerify` → `<VerifyCodeModal>` retry. `tools/check_mounts.py` guards both `{ key: "agents"` and `tab === "agents"`: the nav entry without the body is an empty tab, the body without the nav entry is unreachable, and neither throws.
  - `p_payload` is sent **only when the owner actually edited the draft** — passing an unchanged copy would still stamp `edited: true` in the audit log and turn "the owner rewrote this" into noise. The editor is raw JSON on purpose: payload shape is per-kind and unsettled, and a typed form would silently drop fields it didn't know about. A parse failure refuses rather than sending a half-read object.
  - `agentsFailed` and `actionsFailed` are kept **separate** — the roster answering while the queue breaks is a real state, and collapsing them would render a confident "no agents, nothing pending" for a read that never happened. Times arrive pre-formatted (`created_local`, `expires_local`, `last_run_local`) from `ff_local_ts`; never re-format them in the browser. Expiry is stated in words rather than implied by a greyed button, because a control that can never succeed is worse than no control.
- `admin_rank_contractors`, `admin_list_chat_flags`, `admin_list_picks`, `admin_list_accounts`, `admin_get_contractor_detail`, `admin_resignup_matches`, `admin_audit_tail`, `admin_list_agent_actions` and `admin_agent_overview` are `is_admin()`-gated **reads**.
- **The destructive RPCs are gated harder (2026-11-03): `admin_guard()` = `is_admin()` AND `mfa_ok()`**, plus a `log_admin_action` call immediately after the guard. Thirteen of them: `admin_delete_job`, `admin_delete_request`, `admin_set_contractor_status`, `admin_rescue_signup`, `set_platform_mode`, `admin_refire_request`, `admin_queue_outreach`, `admin_import_outreach`, `admin_rotate_social_bot_key`, `admin_review_social_action` (now a wrapper over `admin_review_agent_action`, which carries the guard itself), `release_waitlisted_requests`, `assign_job`, `admin_clear_mfa`. The three admin **edge** functions (`admin-delete-account`, `admin-update-email`, `admin-message`, all v8) can't call `mfa_ok()` — they hold a service-role client and have no `auth.uid()` — so they call `admin_action_allowed(caller)` instead, which answers the same question for a named id and **fails closed**. Reads deliberately keep plain `is_admin()`: the factor is delivered by our own Resend mailer, and a mailer outage must never blind this dashboard. **All of it is a no-op until the admin account actually enrols** — `mfa_ok()` returns true for anyone not enrolled, which is also why adding these gates couldn't lock anyone out.
